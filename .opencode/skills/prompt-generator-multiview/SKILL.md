## 1. 技能定位
把三视图 / 四视图设定表需求按**三类结构**拆解，输出中英双语正负提示词、推荐模型与参数。

本技能只做文本编排：**不读取、不搜索图片文件**。参考图由出图平台接收，提示词里只用文字引用它。

## 2. 解析流程

### 2.1 模式识别（语义判定，按顺序命中即定）

以用户**意图**为准，关键词仅作锚点，不作穷举匹配。判别关键：是否有一张具体原图要作为设定表的主体来源？还是只借用某图的风格 / 属性而重新生成画面？

1. **无原图，或只借用某图的风格 / 配色 / 画风而重新生成设定表** → `txt2img`
   - 借用的属性写入风格类。
   - 锚点短语（非穷举）：`参考…的画风`、`类似…的风格`、`照这个氛围`
   - 出现「参考图」不等于要绑定原图主体。
2. **以一张已有图为起点，主体外观由参考图决定，产出设定表** → `img2img`
   - 锚点短语（非穷举）：`用这张角色图做设定表`、`以这个人物为准`、`依据上传的图`、`图1 / 第一张`
   - 必须写主体类别词锚点。
3. **其它** → `txt2img`。

> - 判据冲突或表述歧义时在 tips 写明按哪种理解输出；「是否保留原图主体」显著影响结果时追问一句。
> - 不得因关键词缺失就默认 `txt2img` 并强行编造主体外观。
> - 平台术语 `img2img` 命中时直接对应，但仍按上述判据复核意图。

### 2.2 拆解字段（三类 · 顺序不可打乱）

按 **风格 → 主体 → 版式** 组织，正向提示词也按此顺序拼接。

| 类 | 包含 | 说明 |
|---|---|---|
| 1. 风格 style | **画面类型 / 媒介**：角色设定表、物体设定表、工业正交参考图<br>**画风 / 美学**：写实摄影、赛璐璐平涂、工程线稿 | 两层分列，先写类型再写画风；画面类型可直接命中 §2.3 模型推荐 |
| 2. 主体 subject | 主体类别与数量、外观特征（形貌 / 配色 / 服饰）、主体材质、姿态、画面文字（标注） | 姿态固定 T-pose 标准站立，禁止动态姿势；外观、材质与姿态合并 |
| 3. 版式 layout | **视图与排列**：三视图 / 四视图、独立分栏、分割线、横向排布、画面不重叠<br>**正交约束**：物体强制「正交视图，无透视」；人像禁止该词<br>**固定呈现**：纯白 / 浅灰背景、均匀柔光、全身完整入镜 | 三视图不存在景别 / 焦距 / 景深，不写镜头参数 |

> - 顺序不可打乱，类内按「整体 → 细节」排列；段内逗号、段间分号（§4.4）。
> - **版式层的固定规则必须写出**（设定表需要完整骨架）；其余项用户未提及时在「📝 拆解明细」中记 `—`，提示词正文省略，不凑词。
> - 画质词（高清 / 8K / masterpiece 等）不单独成字段、不默认输出；仅用户明确要求时写一个短语。
> - `img2img` 不写具体外观属性值，外观由参考图决定；但【必须】写主体类别词（如「二次元动漫少女」「不锈钢水壶」）。参考图含多主体时先追问哪个是主体，问不到按「画面中央最突出者」处理并在 tips 说明。
> - `img2img` 允许「属性项 + 与参考图一致」写法；用户显式要求改某项外观时，只写被要求改的那一项。
> - **多图时每张图的用途由用户指定；未指定先追问，确实问不到则按用户给出的顺序做中性引用（不擅自分配身份 / 画风角色），并在 tips 说明。参考图按顺序传入，平台指代需可区分。**
> - `img2img` 的参考图只是文本层软约束，真正锁身份靠参考图组件 / IP-Adapter；不写「完全保留 / 完全一致 / 不出现」这类绝对化或排他措辞。
> - 用户明确排除的效果移入负面词。

### 2.3 模型推荐

| 需求特征 | 推荐模型 | 理由（写区分度，禁止写「快」） |
|---|---|---|
| 中文自然语言描述、分栏语义理解 | qwen-image-2.1 | 中文语义理解最强 |
| 二次元 OC / 动漫角色设定表 / 赛璐璐 | Z-Image-Turbo | 二次元画风调度稳定 |
| 物体 / 产品 / 工业正交三视图 | FLUX.2-klein | 结构稳定、几何一致 |
| 真人 img2img、参考图编辑 | FLUX.2-klein | 参考图编辑原生（锁 ID 仍靠 IP-Adapter 等外部组件） |
| 需要 bbox 分栏定位、带标注文字 | MOSS-Image SFT | bbox 布局可控（仅 t2i） |

> - 混合需求输出首选 + 备选；用户指定模型则遵从，理由写「用户指定模型」。
> - 风格层的「画面类型 / 媒介」可直接用于命中本表。

### 2.4 负面词包（直接取用，不自行发明）

按风格层的画面类型取包：

| 画面类型 | 中文 | English |
|---|---|---|
| 写实人像 / 角色设定表 | 肢体畸形，五官扭曲，手指错乱，画面互相融合重叠，不同人物，多余人物，动态姿势，透视混乱，文字，水印，logo | deformed limbs, distorted facial features, malformed fingers, merged panels, different people, extra people, dynamic pose, broken perspective, text, watermark, logo |
| 动漫 / 赛璐璐设定表 | 角色长相不一致，分栏画面融合，肢体崩坏，多余肢体，多余人物，扭曲变形，文字，水印，杂乱背景 | inconsistent character appearance, merged panels, broken limbs, extra limbs, extra people, distortion, text, watermark, cluttered background |
| 物体 / 工业正交 | 透视畸变，画面重叠，物体变形，多余部件，阴影杂乱，文字，水印，环境杂物 | perspective distortion, overlapping panels, object deformation, extra parts, messy shadow, text, watermark, miscellaneous objects |

> - 是否输出按 `CFG` 判定（§2.5）：`CFG=1` 时负面词不参与计算，两节**整节省略**，把用户明确排除的元素改写为正向排除句追加到正向提示词末尾；`CFG>1` 时正常输出。
> - 通用兜底（畸变，模糊，噪点，低质量 / distortion, blurry, noise, low quality）可叠加到任一画面类型。
> - 单图多主体时追加「多余人物，多个主体」/ `extra people, multiple subjects`。

### 2.5 参数基线（2026-10 快照 · 经验起始值）

| 模型 | 变体 | denoise（i2i） | steps | CFG |
|---|---|---|---|---|
| qwen-image-2.1 | 标准版 | 0.6~0.75 | 20~30 | 2.5~4.0 |
| qwen-image-2.1 | Turbo | 以管线为准 | 8 | 1.0 |
| Krea2 Turbo | turbo | 0.6~0.7 | 6~8 | 1.0 |
| FLUX.2-klein | 蒸馏 | 0.55~0.7 | 4~6 | 1.0 |
| FLUX.2-klein | Base | 0.55~0.7 | 20~28 | 3.5~4.0 |
| Z-Image-Turbo | turbo | 0.6~0.7 | 8~10 | 1.0 |
| MOSS-Image | SFT | —（仅 t2i） | 25~30 | 4.0~5.0 |

> - 变体必须注明：FLUX.2-klein（蒸馏 / Base）、MOSS-Image（SFT 出图 / Base 微调）、qwen-image-2.1（标准版 / Turbo）
> - **Turbo / 蒸馏变体 CFG 恒为 1**（引导已内嵌）；CFG 列只填主采样值。公开资料可查：Qwen-Image-2.1-Turbo 为 8 步蒸馏版、CFG=1（2026-10 发布）；其余为经验值，以实际平台为准
> - Turbo 系无 Base 变体，提质量走二段采样：放大 1.5× + denoise 0.35~0.45；第二段 CFG 可取 1.3~1.5，届时按该值单独判定负面词（§2.4），不写进上表 CFG 列
> - qwen-image-2.1 Turbo 的 denoise 未见公开基线，按实际平台填写，不要臆造数值
> - 官方可查：Z-Image `max_text_length` 512、FLUX.2 `max_sequence_length` 512、MOSS 约 4K token

## 4. 分辨率与排版约束

### 4.1 分辨率显存映射

| 显存 | 分辨率 | 说明 |
|---|---|---|
| ≤6G | 1024×768（4:3）| 用 FP8 量化，不开高清修复 |
| 8G | 1536×1024（3:2） | 三/四视图默认 |
| 12~16G | 1792×1024（16:9） | 四视图更宽松 |
| 24G+ | 2048×1152 | 高清设定图 |

> 默认 1536×1024；不用 1024×1024 正方形（横向不足易挤压）；须为 16 的倍数。

### 4.2 提示词书写风格

提示词是「给模型的画面清单」，不是文章。原则：简明扼要，一个属性只写一次。

- 用词语或短语，避免完整长句与叙事铺陈；不堆同义词，不写抽象评价词。
- 段内逗号、段间分号（§4.4）；分号数 = 实际段数 − 1，句尾不加分号。
- 短而准优于长而全；不设字数下限，不为凑长度扩写。
- 只保留官方可查的 token 上限作为硬边界：Z-Image 512（可调 1024）、FLUX.2 512、MOSS 约 4K；其余模型未公布，按上述风格书写。

### 4.3 超硬上限裁剪顺序

仅在确实接近硬上限时触发：先删画质词与泛化修饰 → 再删版式细节（分割线、留白等）与主体材质 → 必须保留风格、主体、分栏核心（视图数与排列、正交约束）。裁掉的内容不转入负面词。

### 4.4 排版规则

1. 中英一一对应，单条内不混排；型号、品牌名保留原文。
2. 中文用中文逗号与全角分号、英文用英文逗号与半角分号；中英分号数量相等。
3. 不用 `(word:1.2)` 权重语法；强调改用语序前置或独立短句。

## 5. 边界与失败模式

以下情形均在 tips 说明原因与替代建议：
1. 需求不属于本技能范围 → 明确拒绝
2. 信息极少 → 用版式层固定规则补齐骨架，不编造离谱主体
3. 用户指定模型无法胜任当前模式（如 MOSS 做 img2img）→ 遵从指定，给出更优备选
4. 人 + 物体混合多视图 → 提示排版崩坏风险，优先主主体；要求正方形输出 → 提示横向空间不足易挤压
5. 参考图张数超平台上限（FLUX.2-klein 约 4 张）→ 提示用户指定保留哪些图，不擅自截断；显式文字优先，文字与参考图冲突时在 tips 提示

## 6. 输出前自检

1. 判定与分流：`task_type` 按 §2.1 语义判据命中；仅借用风格 / 配色未误判为 `img2img`；歧义已在 tips 说明
2. 正文：三类顺序为 风格 → 主体 → 版式，段内逗号、段间分号，中英一一对应；未堆同义词与抽象评价词，画质词未默认输出
3. 参数与负面词：与 §2.5 一致（变体、CFG、denoise），Turbo / 蒸馏 CFG 为 1；负面词按 §2.4 依 `CFG` 判定，`CFG=1` 时两节已省略；分辨率符合 §4.1 且为 16 倍数
4. 版式特有项：视图数与排列、物体带正交 / 人像未带、固定呈现规则已写出；`img2img` 已写主体类别词锚点、未写具体外观值；多图用途按用户指定（未指定已追问或在 tips 说明），张数未超平台上限
5. 未超官方 token 硬上限，超限已按 §4.3 裁剪，未裁掉风格 / 主体 / 分栏核心
