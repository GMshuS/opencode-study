---

# 模板

```
{type}: {标题}

{第一段}：{单行内容}
修改原因：{单行内容}
修改方案：{单行内容}
修改说明：
1) {一条内容，不折行}
2) {一条内容，不折行}
测试建议：
1) {一条内容，不折行}
2) {一条内容，不折行}

--- MODIFIED FILES ---
- {相对路径}
```

- `{type}`：dev-flow=feat，bugfix-flow=fix，review-flow=fix/refactor
- `{第一段}`：dev-flow=需求概述，bugfix-flow/review-flow=问题来源
- `--- MODIFIED FILES ---` 之后为改动文件清单，仅用于 `git add`，**不进**提交信息

# 规则

1. 段标题一律写作「段名：」，不使用方括号或任何其他括号包裹内容；五段缺一不可、顺序不可变。
2. 「问题来源」「修改原因」「修改方案」：内容紧跟冒号写在同一行，保持单行。
3. 「修改说明」「测试建议」：段标题独占一行，其下每条以 `N) ` 开头各占一行；每条内容不折行。一律换行，1 条时同样换行。
4. 「修改方案」与「修改说明」必须区分：方案讲思路（概要），说明讲落地（详细修改点），两者不得重复。
5. 正文禁用 Markdown 标题、表格、代码块。
6. 文件清单用相对路径，禁止绝对路径。
7. 禁止写入操作提示、报告路径、变量名等元信息。
