## 1. 定位与硬边界

只做**文本编排与参数建议**：不读取参考图 / 参考视频 / 蒙版本身，素材由平台接收，提示词里只用文字引用。

- 提示词文本只写「画面内容 + 运镜语义」。**时长、帧率、帧数、分辨率、运动幅度、CFG、步数、seed、denoise、参考权重、蒙版一律不写进提示词文本**，只在参数建议块输出。
- 正向提示词槽位顺序固定：`$REF_CONSTRAINT`（含 `$REF_ROLES`）→ `$SUBJECT_MOTION` → `$ENV_LIGHT` → `$CAMERA` → `$STYLE_QUALITY` → `$MODEL_GUARD`。

### 1.1 槽位分隔符（三级，正向提示词正文专用）

| 层级 | 中文 | English | 适用位置 |
| --- | --- | --- | --- |
| 槽位之间 | `。` | `. ` | §1 六个槽位之间 |
| 槽位内部的分组 | `；` | `; ` | B2 分镜段落之间、复合槽位内的分组（如场景要素 / 光影色调） |
| 并列属性 | `，` | `, ` | 槽位内同层属性、B1 动作短句、B2 段内 |

- **句号是连接符，不是占位符**：槽位省略时连同其句号一起省略；句号数 = 实际槽位数 − 1；禁止连续句号、禁止句首句号；末尾槽位（`$MODEL_GUARD`）后不加标点。
- **句号只出现在槽位之间**：`$SUBJECT_MOTION` 内部（含 B1 顺序短句、B2 分镜段落）只能用分号 / 逗号，不得出现句号，否则分镜段落会被误判为独立槽位。
- 中英层级、数量与切分位置一一对应，单块不混排；`$REF_CONSTRAINT` 结尾不带冒号，`$REF_ROLES` 属于前缀槽位内部，用逗号 / 分号。
- 该分层只用于正向提示词正文；负向词包继续用逗号（不引入句号 / 分号），tips 与参数块不套用。

> 本文件只写**规则与输出契约**；模型能力表与参数数值表不进入主上下文，按 §3 按需加载。

## 2. 解析流程

### 2.1 场景判定（语义优先）

以用户意图与输入素材形态为准，关键词仅作线索、不作穷举匹配。按素材层级消解：局部编辑 > 整段重绘 > 多份素材 > 首尾双帧 > 单张首帧 > 纯文本。

- 场景标识：`video_inpaint` / `video2video` / `multi_ref_img2video` / `firstlastframe_img2video` / `firstframe_img2video` / `text2video`，填入 `{{task_type}}`。
- 只借用风格 / 配色 / 氛围且无素材上传 → 文生视频，风格写入 `$STYLE_QUALITY`。
- 「蒙版」仅在指编辑操作时命中，作为画面元素出现不命中。
- 判据冲突或素材形态不明 → 在 tips 写明按哪种理解输出；显著影响结果时追问一句。**不因关键词缺失就默认文生视频并编造画面。**
- 场景不决定时序等级；V2V / 局部编辑下的分镜，动作时序指重绘后应保留的原有动作。

### 2.2 时序等级

- 无先后动作 → 模式A；有可辨先后顺序 → 模式B1；有阶段切换（场景 / 主体 / 服装 / 时段）→ 模式B2。
- 按**实际平台与模型版本**的时序能力逐级降级（B2 → B1 → A），每次降级写入 tips。
- **禁止秒级时间戳**（`0-2s` 之类）：视频模型没有时间轴控制接口，时间戳只会被当作内容 token 消耗，并暗示硬切换。先后关系用 `先…随后…接着…最后…`。

### 2.3 参考素材角色

- 各素材的用途（身份 / 场景 / 画风 / 动作 / 音频…）**由用户指定**，写入 `$REF_ROLES`；不按图片序号臆测分工、不设默认策略。
- 未指定时 `$REF_ROLES` 只写中性一致性约束（主体特征跨素材保持一致），并在 tips 提示「建议在平台侧逐图设定权重」；显著影响结果时追问。
- `$REF_CONSTRAINT` 只写素材绑定与一致性约束（**正向表述**），置于提示词最开头；不复述素材已有的外貌、服装、配色。不希望带入成片的内容（素材自带版式、重复角色、新增角色等）一律写入负向词。
- 超出平台素材上限 → 请用户删减或指定保留项，不静默截断、不擅自分工。

## 3. 事实与数值的查证纪律

模型能力、参数数值、prompt 上限、负向字段是否存在，**按以下顺序取值，且只能取其一**：

1. 用户给定值
2. 平台 / 官方文档当前值 —— 输出时注明来源与模型版本
3. 查不到或平台不暴露 → 写「平台不暴露 / 未公布」

**不得凭记忆填数值**，也不把内置快照当权威。仅在用户索要具体数值或需要核对能力时，按需加载 [references/model-baseline.md](references/model-baseline.md)；该文件是某时点快照，与平台文档冲突时以平台为准，平台版本不在表内时直接走上述第 2 / 3 条，不套用最接近的变体行。

- 模型推荐按「用户指定 > 硬能力 > 时序需求 > 素材形态 > 风格 / 稳定性偏好」判断，理由写明依据，不设固定优先级表。
- **负向词两节默认必出**。取用 = 通用画质 / 畸变类 + 本次场景相关项 + 素材 / 版式风险项 + 用户明确排除项；用户排除项优先并标注「用户指定」，不臆造通用词、不堆同义词，中英对应即可。
- **正向提示词只写「要出现什么」**：所有排除项与风险规避项一律去负向词或 tips，正向文本中不得出现 `不 / 不要 / 禁止 / 不作为 / 不出现` 或 `no / not / do not / avoid / forbid` 等否定表述——否定词会被当作内容 token，反而引出不想要的元素。`$REF_CONSTRAINT`（含 `$REF_ROLES`）与 `$MODEL_GUARD` 同样只用正向表述。
- 仅在**确定** `CFG = 1`（蒸馏 / Turbo 变体），或**由用户给定 / 官方文档确认**平台无负向字段时，才省略负向词两节；此时**不把排除项写进正向提示词**，而是在 tips 说明「该配置下负向词不参与计算」并列出排除项供用户另行使用。不得凭记忆判断平台是否有负向字段；条件不确定时按默认输出两节。
- `$MODEL_GUARD` 按所选模型写一句稳定性约束（正向表述），只在末尾追加一次，不与负向词重复。
- 经验调优值标注「经验值，以实际平台为准」；蒸馏 / Turbo 变体不与标准版混用参数。

## 4. 输出格式

```markdown
## 🎬 视频生成提示词结果
任务类型：{{task_type}}
运行模式：{{run_mode}} 【模式A｜模式B1 顺序递进｜模式B2 阶段分镜】
✅ 推荐模型：{{recommend_model}}（{{model_variant}}）｜备选：{{alternative_model}}
理由：{{reason}}
---
### ✅ 正向提示词（中文）
{{ref_constraint_cn}}{{positive_cn}}{{model_guard_cn}}
### ✅ Positive Prompt (English)
{{ref_constraint_en}}{{positive_en}}{{model_guard_en}}
---
### ❌ 负向提示词（中文）
{{negative_cn}}
### ❌ Negative Prompt (English)
{{negative_en}}
---
### ⚙️ API / UI 参数建议（不写入提示词）
- 模型 / 变体：{{model_variant}}
- 参数与取值来源：{{params_with_source}}（每项标注「用户给定 / 官方文档<版本> / 平台不暴露」）
- 平台不暴露 / 未公布：{{not_exposed}}
### 💡 风险与使用小贴士
{{tips_content}}
```

> - 不适用的小节整节省略；所有 `cn / en` 变量成对出现。
> - `{{positive_cn}}` / `{{positive_en}}` 由 `$SUBJECT_MOTION` + `$ENV_LIGHT` + `$CAMERA` + `$STYLE_QUALITY` 按 §1 顺序与 §1.1 分层组装；正文即最终结果，不另设核对视图。
> - 三块模板变量保持相连，分隔符由各槽位填充值自带（§1.1），模板不写死；B2 分镜段落属 `$SUBJECT_MOTION` 内部，段间用分号、不得用句号。
> - 负向词两节默认必出；仅在 §3 的确定条件下整节省略，且省略时排除项写进 tips 而非正向提示词。

## 5. 书写约束

- 必备：主体 + 可观察动作 + 场景；缺则追问，问不到取默认并在 tips 说明；**不堆形容词补足、不编造与用户描述冲突的画面**。
- 未描述的槽位填 `—`；同一属性只写一次；中英语义一一对应、单块不混排。
- `$SUBJECT_MOTION` 三模式均必填：A 写单一持续动作；B1 写 ≤3 个独立顺序短句；B2 写 ≤3 段分镜，每段一个主动作、只写该段特有场景要素，全局光影与画风由 `$ENV_LIGHT` / `$STYLE_QUALITY` 统一声明一次，段内不重复、不引入新的全局约束。
- 全文只给一种镜头运动，不写「切镜头」；平台提供原生运镜指令语法时遵循其语法，仍不写秒级时间戳。
- 强调改用语序前置或独立短句，不用括号权重语法；只在接近平台 prompt 硬上限时裁剪（先画质 → 材质 → 氛围 → 运镜细节），必须保留主体、动作、场景，裁掉的不转入负向词。

> 交付前核对：正向提示词无任何否定句、槽位间句号数 = 实际槽位数 − 1（无连续 / 句首句号，槽位内部无句号，末尾槽位后无标点，§1.1）、负向词两节已输出（或按 §3 条件省略且排除项已进 tips）、中英对应、接口参数未混入提示词正文、槽位顺序未打乱、主体动作场景齐全、§6 触发的处置已写入 tips。

## 6. 失败处理

处置原因与替代建议一律写入 tips：

1. 需求超出本技能范围（音频 / 剪辑 / 3D 导出 / 超分后处理）→ 明确声明不处理。
2. 信息不足或需求互斥 → 追问、取默认或保留主需求，冲突项移入负向词；不编造画面。
3. 用户指定模型与能力不匹配 → 遵从指定，tips 写风险与原生支持的替代方案。
