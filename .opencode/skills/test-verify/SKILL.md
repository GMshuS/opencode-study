# 测试验证 Skill

## 核心原则

- **优先项目脚本** — 有 `scripts.test` / Makefile `check` / ctest 等就用项目的，不自行拼命令
- **只报告不修复** — 不改业务代码、不改测试
- **无测试 ≠ 通过** — 检测不到测试标记跳过并说明，不判失败，但结论须提示"未覆盖测试验证"
- **跑不起来 ≠ 失败** — 测试未能启动标记 `⏭️ 未执行 / 阻断 — 原因`，不记通过也不判失败
- **防挂死** — 默认 300s 超时；超时记 `❌ 超时`，禁止静默当通过

## 工作流程

1. **前置检测**：检测测试框架是否已安装；需预构建的语言（C/C++ 等）还须检测构建产物是否存在，
   不存在 → `⏭️ 未执行 — 未找到构建产物，请先执行构建`（**本 skill 不自行构建**）
2. **执行测试**：测试**已启动**但用例断言失败 → `❌ 失败`；**未能启动** → `⏭️ 未执行 / 阻断 — 原因`
3. **报告**：

```
═══ 测试验证报告 ═══
  框架/命令: {...}
  结果: {a} 通过 / {b} 失败 / {c} 跳过 / {❌ 超时}
  失败详情: ❌ {用例名} — {文件:行} — {断言消息 / 原始输出}

═══ 结论: {✅ 通过 | ❌ N 项失败 | ⏭️ 跳过 — 原因 | ⏭️ 阻断 — 原因} ═══
```
