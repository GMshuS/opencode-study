# 图片条件生成（img2img）提示词规范

## 0. 定位

本文档覆盖**所有带图片输入的生成**：初始化图片、蒙版、参考图及其组合都属于 `img2img`，差异只在输入条件。只规定「如何思考」与「什么算合格」；所有措辞由模型按本次输入生成，文中词句只用于说明结构或标明反例，不得当作模板或默认词。不套模板、不做填空、不受固定情形枚举限制。

## 1. 输入条件清点

先清点本次传入了哪些图片条件；条件可组合，并让提示词中的指代全程一致。

| 条件 | 数量 | 控制量 | 作用 |
|---|---|---|---|
| 初始化图片 | 至多 1 张 | `denoise` | 像素作为生成起点，被继承的程度 |
| 蒙版 | 0/1 张 | — | 作用于初始化图片，限定重绘区域 |
| 参考图 | 0~N 张 | 参考强度（平台相关） | 提供主体 / 背景 / 风格 / 配色 / 氛围等特征，不继承像素 |

- 只有一张初始化图片且无其它图片时可用「原图」；存在多张图片时须写明是哪张图、什么条件、从哪张图取什么，禁止无指向的「原图」「周围画面」。
- 跨图引用写成可区分的形式，如「参考图1（主体）」「参考图2（风格）」；每个指代都须唯一可解析。
- 参考图提供的内容**写成绑定指代，不翻译成文字细节**：用户只说「形象参考图1」时，不得自行写出该形象的五官、材质、姿势等具体描述。
- 条件无法判断时在「💡 小贴士」说明所取理解，影响结果时追问一句；不臆造图片。
- 本次用了哪些条件、图片如何绑定、平台能力前提写在理由与「💡 小贴士」；`task_type` 统一写 `img2img`。

## 2. 条件决定提示词写法

| 条件组合 | 提示词主要内容 |
|---|---|
| 有初始化图片 | 描述改动：哪些内容守住、改成什么、如何衔接 |
| 只有参考图（无 init） | 描述目标画面：按语义分段写出要生成的画面，同时声明参考图绑定 |
| 两者组合 | 先声明绑定与保留项，再写新生成的内容，最后写衔接 |

- 动词（换成 / 改为 / 去掉 / 参考）只作线索；判断依据是「本次有没有像素起点、图片各提供什么」。
- 蒙版不是独立类型，只是把改动限定在特定区域；区域可由对象名、位置词给出，用户点名具体元素也算可定位。
- 背景 / 天空等大范围替换未指定蒙版时按整幅处理；判定歧义且影响结果时在「💡 小贴士」写明所取理解与替代路径。
- 条件不反过来限制提示词：段数、段落职责、措辞一律由本次目标决定。

## 3. 正向提示词的生成

### 3.1 每次重新推一遍

1. 本次要生成 / 改动什么？从用户描述抽取目标，不编造用户没提出的内容。
2. 哪些图片条件必须被绑定或守住？据此决定基准段写什么、锚定到哪张图、锚定哪些属性。
3. 新内容会波及哪些相邻属性？据此决定是否写衔接段、写哪几个方面。
4. 按「基准 → 变更 → 衔接」组织；不需要的段整段省略（连同其分号）。

### 3.2 段落只定义职责

| 段 | 要回答的问题 | 内容来源 |
|---|---|---|
| 基准 | 以哪些图片条件为基准 / 绑定什么、守住什么 | 由目标反推，只写本次真正需要绑定或守住的内容 |
| 变更 | 要生成什么画面、改成什么样、内容取自哪里 | 用户原话 + 必要的可观察细化 |
| 衔接 | 新内容与相邻内容在哪些方面要接得上 | 由条件组合与改动位置按需选取 |

- 段数、段序不固定；不把「构图 / 光影 / 色调」当默认三件套，与目标无关的锚点是噪声。
- 不编造图中没有的元素；主体只写类别词、绑定指代或角色指代。
- 不写「其余元素全部不变」这类冗余指令，也不用 `Mask area:` 之类标签。

### 3.3 图片条件下的取舍

允许为让画面成立而补齐可观察描述（光影、透视、比例、材质表现、细节层次等），措辞由模型生成；具体材质 / 物件 / 风格名不得当作默认输出，参考图已提供的内容不得自行改写为文字细节。

### 3.4 失效模式（反例，仅用于自检）

| 情形 | 不合格表现 | 原因 |
|---|---|---|
| 用户说「形象参考图1」 | 提示词里没有参考图指代，改写成一堆自编外观细节 | 参考图被翻译成文字，绑定丢失 |
| 用户只说「提升质感」 | 出现某种具体材质名称 | 擅自具体化，把示例当默认词 |
| 两张以上图片做局部替换 | 出现无指向的「原图」指代 | 指代不唯一 |
| 多张参考图生成新画面 | 因没有对应情形而套用模板或拒答 | 用枚举代替理解 |
| 只有参考图、无 init | 仍给出 denoise 建议，或写「以原图为基准」 | 条件判断错误 |
| 用户描述简略 | 只做直译、不补齐必要维度 | 未执行默认扩写 |
| 任何需求 | 段落数由条件名决定、句式与旧模板雷同 | 填空题式输出 |

> 这些只用于自检，不是替换表。

## 4. denoise 联动（仅有初始化图片时成立）

`denoise` 只对初始化图片有意义：控制原图像素被继承的程度。纯参考图路径不填 `denoise`；若平台提供参考强度则按平台填写，不臆造数值。

| denoise | 文本层取舍 |
|---|---|
| 低（约 <0.55） | 保留已由参数保证，基准类约束可极简或省略，正文聚焦变更项 |
| 中（约 0.55~0.7） | 写一条与本次改动相关的基准约束 |
| 高（约 >0.7） | 文本约束效果有限，不要靠加重措辞补偿；在「💡 小贴士」提示降低 denoise 或改用蒙版限定区域 |

> 带蒙版时区域外由蒙版保证保留，蒙版内仍需充分重绘；不因 denoise 较高而弱化文本或额外告警。

## 5. 负面词风险维度

仅作启发，按需组合、不设取值枚举、不原样照抄：身份 / 结构漂移、原风格残留、材质或光照割裂、边缘错位与拼接痕迹、修改区域外被改动、局部畸变、多余主体、人物五官与手指异常。

## 6. 输出

- `task_type` 统一写 `img2img`；输入条件标注在理由与「💡 小贴士」。
- 参数建议：有初始化图片时 `denoise` 必填，蒙版重绘用其专属区间；纯参考图路径 `denoise` 写 `—`。
- 图片绑定、蒙版归属与平台多图能力前提写在「💡 小贴士」。
