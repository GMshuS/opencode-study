## 1. 技能定位

把生图提示词需求按是否有图片输入分流，把用户（往往简短的）描述扩写、优化为完整可用的提示词。覆盖：

- 纯文字生成 `txt2img`：无图片输入
- 图片条件生成 `img2img`：有图片输入即属此类；条件包括初始化图片（至多 1 张，`denoise` 控制重绘程度）、蒙版（限定重绘区域）、参考图（可多张，提供主体 / 背景 / 风格 / 配色 / 氛围等特征，不继承像素），可组合
- 图片反推 `reverse`：根据会话中可见的图片，产出描述「风格 → 主体 → 场景」的提示词，并按用户要求调整；输出为文本，不属于生图

本技能只做**文本编排**：不主动读取、不搜索图片文件，也不调用视觉识别工具。图片由出图平台接收，提示词与输出须声明其条件与绑定关系；反推依赖宿主在会话中提供的可见图像。

> 本文件是入口与共享层；各分支专属规则在 `references/` 下按 §2.2 加载。共享规则只在此声明一次，分支文档不重复、不引用本文件章节。

## 2. 解析流程

### 2.1 任务识别（按是否传入图片，按顺序命中即定）

顶层判据只有一条：**本次是否传入图片用于生成**。措辞只作线索，不以「参考」「换」「风格」等字面表述判定。

1. **求提示词 / 反推**：输入是图片，但输出是提示词文本，不是生图 → `reverse`
   - 锚点短语（非穷举）：`根据这张图写提示词`、`反推`、`这张图用了什么提示词`
2. **无图片输入，纯文字描述** → `txt2img`
   - 写在文字里的风格 / 配色 / 氛围（如「水彩风」「胶片质感」）属于本类；只有会话中实际传入图片才算图片输入。
3. **有图片输入用于生成** → `img2img`
   - 前置清点条件：初始化图片（至多 1 张，`denoise` 生效）、蒙版（作用于初始化图片）、参考图（0~N 张，提供主体 / 背景 / 风格等特征，不继承像素）。条件可组合。
   - `task_type` 统一写 `img2img`；本次用了哪些条件、图片如何绑定、平台能力前提，写在理由与「💡 小贴士」。
   - 「局部重绘」「参考图生成新画面」「初始化图片 + 多张参考图」都是条件组合，不是并列类型。
   - 锚点短语（非穷举）：`这张照片调成…`、`以这张图为底`、`把…换成…`、`去掉水印`、`形象参考图1`、`按这张图的配色`
4. **其它** → `txt2img`。

> - 判据冲突时，在「💡 小贴士」写明按哪种理解输出；当「是否有图片输入」显著影响结果时追问一句。**不得因关键词缺失就默认 `txt2img` 并强行编造画面。**
> - 平台术语（`img2img` / `inpaint` / `蒙版重绘` / `参考图`）命中时仍按上述判据复核；`inpaint` 与「参考图生成」都是 `img2img` 的条件组合，不是并列类型。
> - 「换成 / 改为 / 去掉 / 参考」等字面表述只作线索，不直接决定类型。
> - **`reverse` 里的「按用户要求调整」是对上一步产出的提示词文本做修改**：
>   用户要改的是提示词 → 留在 `reverse`；明确要改图片本身 → 说明超出反推范围并按 `img2img` 重新判定，在「💡 小贴士」说明。

### 2.3 模型推荐

| 需求特征 | 推荐模型 | 理由（写区分度，禁止写「快」） |
|---|---|---|
| 二次元 / 赛璐璐 / OC | Z-Image-Turbo | 二次元调度稳定 |
| 写实人像 / 原生肤质 / 单行短文字 | Z-Image-Turbo | 肤质自然、短文字准确 |
| 电影氛围 / 逆光 / 胶片 / 发丝飘动 / 情绪向 | Krea2 Turbo | 光影层次与材质表现 |
| 复杂构图 / 多物体 / 产品渲染 / 建筑原画 | FLUX.2-klein | 构图稳定，长 prompt 承载力强 |
| 国风 / 水墨 / 工笔 / 中文叙事 | qwen-image-2.1 | 中文语义与国风语料 |
| 图片条件生成（初始化图片 / 蒙版 / 多张参考图） | FLUX.2-klein 或 qwen-image-2.1 | 两者都原生支持多图输入与蒙版编辑；qwen 局部一致性更强 |
| 成段文字 / 海报版式 / 信息图 / UI / bbox 布局 | MOSS-Image SFT | bbox 布局可控，约 4K token |

> `txt2img` / `reverse` 时，「画面类型 / 媒介」层可直接用于命中本表。

冲突消解：
1. 命中 ≥2 类 → 首选 + 备选，理由写明取舍
2. 成段文字与图片条件生成互斥 → 分两步：先 MOSS 出图，再 img2img 精修
3. MOSS-Image 仅支持 t2i，`img2img` 不选它
4. 用户指定模型 → 遵从，理由写「用户指定」

### 2.4 负面词输出规则

负面词按分支**依本次风险生成**，本文件保留生成原则与输出判定：

- `txt2img` → 依本次画面类型与画风的风险生成
- `img2img` → 依本次图片条件与目标的风险生成
- `reverse` → 默认不输出负面词；用户要求模型 / 参数建议且 `CFG>1` 时，只写与本次风险相关的最小集合 + 用户排除项
- 先判断本次最可能怎么失败，再写出中英对应的失败模式词；用户明确排除的元素优先追加并标注「用户指定」，除此之外不堆与本次风险无关的词
- 通用兜底（畸变，模糊，噪点，低质量 / distortion, blurry, noise, low quality）可按需叠加
- 负面词不得与正文中刻意保留的元素冲突

**是否输出由本次参数建议中的 `{{cfg_scale}}` 决定（取值见 §2.5）：**

`reverse` 默认不输出参数建议，此时没有 `{{cfg_scale}}`，负面词两节一并省略。

| `{{cfg_scale}}` | 处理 |
|---|---|
| `= 1`（Turbo / 蒸馏变体） | 「❌ 负面提示词（中文）」「❌ Negative Prompt (English)」两节**整节省略**；通用兜底一并不输出。用户明确排除的元素改写为正向排除句追加到正向提示词末尾（用独立短句，不改变段数、不新增分号），并在 tips 说明原因 |
| `> 1`（Base / 标准版 / SFT） | 正常输出两节负面词，按分支依风险生成 |

> - 不因「写都写了」而在 `CFG=1` 时保留负面词区块：该配置下负面词不参与计算。
> - Turbo 二段采样的第二段 CFG 若 >1，按第二段实际值单独判定，并在参数建议与 tips 分别标注两段的 CFG。
> - 用户「不要改 X」这类排他需求：不写进正向提示词正文，也不写进 `img2img` 的基准段；`CFG>1` 走负面词，`CFG=1` 改写为正向排除句。

### 2.5 参数基线

| 模型 | 变体 | 支持模式 | steps | CFG | 分辨率 | denoise（整幅 / 蒙版） |
|---|---|---|---|---|---|---|
| Z-Image-Turbo | turbo | t2i、i2i | 8~10 | 1.0 | 1024 起 | 0.6~0.7 / — |
| FLUX.2-klein | 蒸馏 | t2i、i2i、inpaint | 4~6 | 1.0 | ≤4MP | 0.55~0.7 / 0.75~0.9 |
| FLUX.2-klein | Base | t2i、i2i、inpaint | 20~28 | 3.5~4.0 | ≤4MP | 0.55~0.7 / 0.75~0.9 |
| Krea2 Turbo | turbo | t2i、i2i | 6~8 | 1.0 | 1024 起 | 0.6~0.7 / — |
| MOSS-Image | SFT | t2i | 25~30 | 4.0~5.0 | 512~2K 任意比例 | — |
| qwen-image-2.1 | 标准版 | t2i、i2i、inpaint | 20~30 | 2.5~4.0 | 1024 起 | 0.6~0.75 / 0.75~0.9 |
| qwen-image-2.1 | Turbo | t2i、i2i、inpaint | 8 | 1.0 | 1024 起 | 以管线为准 |

> - 变体必须注明：FLUX.2-klein（蒸馏 / Base）、MOSS-Image（SFT 出图 / Base 微调）、qwen-image-2.1（标准版 / Turbo）
> - **Turbo / 蒸馏变体 CFG 恒为 1**（引导已内嵌，无需 classifier-free guidance）；CFG 列只填主采样值，不混写其它阶段的取值。公开资料可查：Qwen-Image-2.1-Turbo 为 8 步蒸馏版、CFG=1（2026-10 发布）；其余为经验值，以实际平台为准
> - Turbo 系无 Base 变体，提质量走二段采样：放大 1.5× + denoise 0.35~0.45；第二段 CFG 可取 1.3~1.5，届时按该值单独判定负面词（§2.4），不写进上表 CFG 列
> - qwen-image-2.1 Turbo 的 denoise 未见公开基线，按实际平台填写，不要臆造数值
> - **`denoise` 只对初始化图片有意义**；纯参考图路径不填 `denoise`，若平台提供参考强度则按平台填写，不臆造数值
> - 分辨率须为 16 的倍数；MOSS 任意比例
> - 官方可查：Z-Image `max_text_length` 512、FLUX.2 `max_sequence_length` 512、MOSS 约 4K token。其余为经验值，非厂商声明

## 4. 提示词书写风格与约束

### 4.1 书写风格

提示词是「给模型的画面清单」，不是文章。原则：简明扼要，一个属性只写一次。

**内容来源（默认扩写）**：用户输入往往简短，默认动作是把它扩写、优化为完整可用的提示词——补哪些维度、用什么措辞由模型按画面逻辑自行判断，不查表、不套模板、不受固定情形枚举限制。允许为让画面成立而补齐**已写出段落内**的一般维度（风格、光线、视角、景别、材质表现、细节层次等）；禁止把具体材质 / 物件 / 颜色 / 风格名当默认输出，禁止引入与用户描述冲突的主体、场景或画风，禁止用形容词或同义词凑长度，禁止因信息不足而新增与用户输入无关的段落。**反推以可观察内容为上限，不适用主动补全；参考图已提供的内容以绑定指代表达，不翻译成文字细节。** 用户明确要求扩写时按其方向进一步细化。

- 用词语或短语，避免完整长句、叙事铺陈与因果解释。
- **段内用逗号，段间用分号**：中文 `，…；` / 英文 `, …; `。
  - `txt2img` / `reverse`：按 **风格 → 主体 → 场景** 组织，按实际写出的类分段；不适用或未识别的段连同其分号省略
  - `img2img`：按实际语义分段（基准 / 变更 / 衔接…），段数由本次内容决定
- 分号是**连接符不是占位符**：某段省略时连同其分号一起省略，分号数 = 实际段数 − 1；禁止连续分号、禁止句尾分号；中英分号数量相等。
- 分号只用于正向提示词正文的段间；负面词、`📝` 明细列表、MOSS 版式文案均不用分号。
- 版式文案原样保留，文案内自带标点不算结构分隔符；正文内除段间外不得再出现分号。
- 同一属性不重复表达，不堆同义词（如 beautiful, gorgeous, stunning 连用）。
- 不用「非常 / 极其 / 超」等程度副词，不用「很美 / 震撼 / 高级感」等抽象评价词；改写为可观察的画面特征。
- 画质词不单独成字段、不默认输出；仅用户明确要求时写一个短语，且不得与其它修饰重复。
- 短而准优于长而全；不设字数下限、不无意义注水；用户描述简略时应主动补全必要维度。

合格判定：每段写的是可观察属性而非评价词；一个属性只写一次；补充的维度与用户描述不冲突；中英一一对应。

### 4.2 硬上限与裁剪

只保留官方可查的 token 上限，作为「不得超出」的硬边界，不作配额或目标：Z-Image 512（可调 1024）、FLUX.2 512、MOSS-Image 约 4K；其余模型未公布，按 §4.1 书写。基准段与衔接段计入其中。

仅在确实接近硬上限时触发裁剪：先删画质词与泛化修饰 → 再删材质与镜头细节 → 必须保留用户明确给出的核心描述；裁掉的内容不转入负面词。

### 4.3 排版规则

1. 中英一一对应，单条内不混排；型号、品牌名保留原文。
2. 中文用中文逗号与全角分号、英文用英文逗号与半角分号；不用多余换行。
3. 不用 `(word:1.2)` 权重语法；强调改用语序前置或独立短句。

## 5. 边界与失败模式

以上情形均在 tips 说明原因与替代建议：
1. 需求不属于本技能范围 → 明确拒绝
2. 信息不足或需求互斥 → 由模型按画面逻辑补全合理维度，影响结果时在 tips 说明所取理解或追问一句；保留主需求，其余按 §2.4 处理；禁止编造与用户描述冲突的主体、场景或画风
3. 用户指定模型无法胜任（如 Z-Image 出成段文案）→ 遵从指定，给出更优备选
4. 反推特有：会话中看不到图片时降级（不臆测画面内容，OCR 只提取文字与版面，不能替代视觉观察）；反推是近似描述，要精确复现请把原图作为参考素材

## 6. 输出前自检
