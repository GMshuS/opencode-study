## 1. 技能定位

把单图生图需求按输入与模式分流，输出中英双语正负提示词，并推荐模型与参数。覆盖：

- 文生图 `txt2img`、图生图 `img2img`、蒙版局部重绘 `inpaint`
- 图片反推 `reverse`：根据会话中可见的图片，产出描述「风格 → 主体 → 场景」的提示词，并按用户要求调整

本技能只做**文本编排**：不主动读取、不搜索图片文件，也不调用视觉识别工具。参考图由出图平台接收；反推依赖宿主在会话中提供的可见图像。

> 本文件是入口与共享层：任务识别、模型推荐、负面词取包规则、参数基线、输出格式、书写风格、边界与自检。
> 各分支专属的拆解结构与组装方式在 `references/` 下，按 §2.2 加载。

## 2. 解析流程

### 2.1 任务识别（语义判定，按顺序命中即定）

以用户**意图**为准，关键词仅作锚点，不作穷举匹配。判别关键：是否上传了图片求提示词？是否要保留某张原图里可识别的画面内容？改动覆盖整幅还是局部？

1. **上传图片求提示词 / 反推** → `reverse`
   - 锚点短语（非穷举）：`根据这张图写提示词`、`反推`、`这张图用了什么提示词`
2. **无原图，或只借用某图的风格 / 配色 / 氛围 / 画风而重新生成画面** → `txt2img`
   - 借用属性写入风格类，不进入编辑分支。
   - 锚点短语：`参考…的画风`、`想要这种感觉`、`类似…的风格`、`按这张图的配色`、`照这个氛围`
   - 出现「参考图」不等于要编辑原图。
3. **以一张已有图为起点，整幅变换且保留其可识别内容** → `img2img`
   - 锚点短语：`这张照片调成…`、`用我上传的图重绘成…`、`保持人物换个风格`、`整体提亮加胶片颗粒`、`以这张图为底`
   - 变换覆盖画风、色调、光线、整体质感等整幅属性。
4. **在一张已有图上，点名局部对象 / 区域做增删改** → `inpaint`
   - 区域可由对象名、位置词或「除 X 外」给出；用户未明说区域但点名了图中具体元素，也算「可定位」。
   - 锚点短语：`把…去掉`、`…换成…`、`…改为…`、`只动一下…`、`去掉水印`、`局部调整`
   - 仅当「蒙版」指编辑操作时才命中；作为画面元素出现（如「蒙版效果海报」）不命中。
   - 背景 / 天空等大范围区域的整体替换，未指定蒙版时按整幅变换处理；仅当明确针对小范围对象或指定蒙版时才判 `inpaint`。
5. **其它** → `txt2img`。

> - 判据冲突或表述既可理解为编辑也可理解为重画时，在 tips 写明按哪种理解输出；
>   当「是否保留原图内容」显著影响结果时追问一句。**不得因关键词缺失就默认 `txt2img` 并强行编造画面。**
> - 平台术语（`img2img` / `inpaint` / `蒙版重绘`）命中时直接对应，但仍按上述判据复核意图。
> - **`reverse` 里的「按用户要求调整」是对上一步产出的提示词文本做修改**：
>   用户要改的是提示词 → 留在 `reverse`；明确要改原图本身 → 说明超出反推范围并按上方编辑类条目重新判定，在 tips 说明。

### 2.2 分支分流

§2.1 判定完成后按表加载参考文档：

| 判定结果 | 加载 | 该文档负责 |
|---|---|---|
| `txt2img` | [references/txt2img.md](references/txt2img.md) | 三类拆解（风格 → 主体 → 场景）、拆解明细、按风格取负面词、版式 `layout`、要素完备性 |
| `img2img` / `inpaint` | [references/img2img-inpaint.md](references/img2img-inpaint.md) | 编辑三段结构、锚点 / 融合句、变更项、denoise 联动、编辑模式负面词 |
| `reverse` | [references/reverse.md](references/reverse.md) | 图像观察 → 三类映射、可观察特征约束、两版输出与调整规则 |

> - 三份参考文档**互斥，只加载对应的一份**；各分支所需的共享规则一律取自主文件，不跨文档引用。
> - `txt2img` 输出中不存在锚点句与融合句；编辑模式不套用三类结构与拆解明细。
> - 正向提示词正文一律按 §4.1 的分号分层规则组装。

共享规则不随分支变化，一律留在本文件：模型推荐（§2.3）、负面词取包规则（§2.4）、参数基线（§2.5）、输出格式（§3）、提示词书写风格与排版（§4）、边界（§5）、输出前自检（§6）。

### 2.3 模型推荐

| 需求特征 | 推荐模型 | 理由（写区分度，禁止写「快」） |
|---|---|---|
| 二次元 / 赛璐璐 / OC | Z-Image-Turbo | 二次元调度稳定 |
| 写实人像 / 原生肤质 / 单行短文字 | Z-Image-Turbo | 肤质自然、短文字准确 |
| 电影氛围 / 逆光 / 胶片 / 发丝飘动 / 情绪向 | Krea2 Turbo | 光影层次与材质表现 |
| 复杂构图 / 多物体 / 产品渲染 / 建筑原画 | FLUX.2-klein | 构图稳定，长 prompt 承载力强 |
| 国风 / 水墨 / 工笔 / 中文叙事 | qwen-image-2.1 | 中文语义与国风语料 |
| 参考图编辑 / 蒙版局部重绘 | FLUX.2-klein 或 qwen-image-2.1 | 两者都原生支持参考图与蒙版编辑；qwen 局部一致性更强 |
| 成段文字 / 海报版式 / 信息图 / UI / bbox 布局 | MOSS-Image SFT | bbox 布局可控，约 4K token |

> - `txt2img` / `reverse` 时，「画面类型 / 媒介」层可直接用于命中本表。
> - `reverse` 默认不输出模型与参数建议；用户要求「顺便给个能复现的模型」时才给，按风格类型命中。

冲突消解：
1. 命中 ≥2 类 → 首选 + 备选，理由写明取舍
2. 成段文字与参考图编辑互斥 → 分两步：先 MOSS 出图，再 img2img 精修
3. MOSS-Image 仅支持 t2i，`img2img` / `inpaint` 不选它
4. 用户指定模型 → 遵从，理由写「用户指定」

### 2.4 负面词取包规则

负面词表按分支存放，本文件只保留取用规则：

- `txt2img` → `references/txt2img.md` 的「按风格取包」（画面类型 → 基础包，画风 → 追加包）
- `img2img` / `inpaint` → `references/img2img-inpaint.md` 的「编辑模式负面词」
- `reverse` → 默认不输出负面词；用户要求模型 / 参数建议且 `CFG>1` 时，只用通用兜底 + 用户排除项
- 通用兜底（畸变，模糊，噪点，低质量 / distortion, blurry, noise, low quality）可叠加到任一分支
- 用户明确排除的元素优先追加，标注「用户指定」；除此之外不自行发明通用词

**是否输出由本次参数建议中的 `{{cfg_scale}}` 决定（取值见 §2.5）：**

`reverse` 默认不输出参数建议（§3），此时没有 `{{cfg_scale}}`，负面词两节一并省略。

| `{{cfg_scale}}` | 处理 |
|---|---|
| `= 1`（Turbo / 蒸馏变体） | 「❌ 负面提示词（中文）」「❌ Negative Prompt (English)」两节**整节省略**；词包与通用兜底一并不输出。用户明确排除的元素改写为正向排除句追加到正向提示词末尾（用独立短句，不改变段数、不新增分号），并在 tips 说明原因 |
| `> 1`（Base / 标准版 / SFT） | 正常输出两节负面词，按分支取包 |

> - 不因「写都写了」而在 `CFG=1` 时保留负面词区块：该配置下负面词不参与计算。
> - Turbo 二段采样的第二段 CFG 若 >1，按第二段实际值单独判定，并在参数建议与 tips 分别标注两段的 CFG。
> - 用户「不要改 X」这类排他需求：`CFG>1` 走负面词，`CFG=1` 改写为正向排除句；**不写进编辑模式的锚点句**。

### 2.5 参数基线

| 模型 | 变体 | 支持模式 | steps | CFG | 分辨率 | denoise（i2i / inpaint） |
|---|---|---|---|---|---|---|
| Z-Image-Turbo | turbo | t2i、i2i | 8~10 | 1.0 | 1024 起 | 0.6~0.7 / — |
| FLUX.2-klein | 蒸馏 | t2i、i2i、inpaint | 4~6 | 1.0 | ≤4MP | 0.55~0.7 / 0.75~0.9 |
| FLUX.2-klein | Base | t2i、i2i、inpaint | 20~28 | 3.5~4.0 | ≤4MP | 0.55~0.7 / 0.75~0.9 |
| Krea2 Turbo | turbo | t2i、i2i | 6~8 | 1.0 | 1024 起 | 0.6~0.7 / — |
| MOSS-Image | SFT | t2i | 25~30 | 4.0~5.0 | 512~2K 任意比例 | — |
| qwen-image-2.1 | 标准版 | t2i、i2i、inpaint | 20~30 | 2.5~4.0 | 1024 起 | 0.6~0.75 / 0.75~0.9 |
| qwen-image-2.1 | Turbo | t2i、i2i、inpaint | 8 | 1.0 | 1024 起 | 以管线为准 |

> - 变体必须注明：FLUX.2-klein（蒸馏 / Base）、MOSS-Image（SFT 出图 / Base 微调）、qwen-image-2.1（标准版 / Turbo）
> - **Turbo / 蒸馏变体 CFG 恒为 1**（引导已内嵌，无需 classifier-free guidance）；CFG 列只填主采样值，不混写其它阶段的取值。公开资料可查：Qwen-Image-2.1-Turbo 为 8 步蒸馏版、CFG=1（2026-10 发布）；其余为经验值，以实际平台为准
> - Turbo 系无 Base 变体，提质量走二段采样：放大 1.5× + denoise 0.35~0.45；第二段 CFG 可取 1.3~1.5，届时按该值单独判定负面词（§2.4），不写进上表 CFG 列
> - qwen-image-2.1 Turbo 的 denoise 未见公开基线，按实际平台填写，不要臆造数值
> - 分辨率须为 16 的倍数；MOSS 任意比例
> - 官方可查：Z-Image `max_text_length` 512、FLUX.2 `max_sequence_length` 512、MOSS 约 4K token。其余为经验值，非厂商声明
> - **`img2img` 下 denoise 才真正决定「保留多少原图」**，锚点句只是文本层的软约束：低 denoise 可极简甚至省略；中 denoise 写一句基准锚点；高 denoise 时文本约束有限，在 tips 提示降 denoise 或改走 `inpaint`，而不是把锚点句写得更强。`inpaint` 的基线 denoise 本就较高（蒙版区域需充分重绘），由蒙版保证其余区域保留，不套用此规则

## 4. 提示词书写风格与约束

### 4.1 书写风格

提示词是「给模型的画面清单」，不是文章。原则：简明扼要，一个属性只写一次。

- 用词语或短语，避免完整长句、叙事铺陈与因果解释。
- **段内用逗号，段间用分号**：中文 `，…；` / 英文 `, …; `。
  - `txt2img` / `reverse`：`风格，…；主体，…；场景，…`
  - 编辑模式：`锚点，…；变更项，…；一致性约束，…`（无融合段时只有两段）
- 分号是**连接符不是占位符**：某段省略时连同其分号一起省略，分号数 = 实际段数 − 1；禁止连续分号、禁止句尾分号。
- 分号只用于正向提示词正文的段间；负面词包、`📝` 明细列表、MOSS 版式文案均不用分号。
- 版式文案原样保留，文案内自带标点不算结构分隔符；正文内除段间外不得再出现分号。
- 同一属性不重复表达，不堆同义词（如 beautiful, gorgeous, stunning 连用）。
- 不用「非常 / 极其 / 超」等程度副词，不用「很美 / 震撼 / 高级感」等抽象评价词；改写为可观察的画面特征。
  例：`非常唯美的逆光人像` → `侧逆光，发丝边缘高光，浅景深`
- 短而准优于长而全；不设字数下限，不为凑长度扩写。

示例：

```text
写实人像摄影，胶片质感；一位银发女性，米白色针织衫，侧身回望，发丝微动；午后窗边，侧逆光，50mm 视角，浅景深
Photorealistic portrait, film grain; a silver-haired woman, cream knit sweater, looking back over her shoulder, hair slightly moving; by a window in the afternoon, side backlight, 50mm lens, shallow depth of field
```

### 4.2 硬上限与裁剪

只保留官方可查的 token 上限，作为「不得超出」的硬边界，不作配额或目标：Z-Image 512（可调 1024）、FLUX.2 512、MOSS-Image 约 4K；其余模型未公布，按 §4.1 书写。锚点句与融合句计入其中。

仅在确实接近硬上限时触发裁剪：先删画质词与泛化修饰 → 再删材质与镜头细节 → 必须保留风格、主体、场景（编辑模式则为变更项）的核心描述；裁掉的内容不转入负面词。

### 4.3 排版规则

1. 中英一一对应，单条内不混排；型号、品牌名保留原文。
2. 中文用中文逗号与全角分号、英文用英文逗号与半角分号；不用多余换行。
3. 不用 `(word:1.2)` 权重语法；强调改用语序前置或独立短句。

## 5. 边界与失败模式

以上情形均在 tips 说明原因与替代建议：
1. 需求不属于本技能范围 → 明确拒绝
2. 信息不足或需求互斥 → 追问、取默认或保留主需求，其余按 §2.4 处理；禁止编造与用户描述冲突的主体
3. 用户指定模型无法胜任（如 Z-Image 出成段文案）→ 遵从指定，给出更优备选
4. 反推特有：会话中看不到图片时降级（不臆测画面内容，OCR 只提取文字与版面，不能替代视觉观察）；反推是近似描述，要精确复现请把原图作为参考素材

## 6. 输出前自检

1. 判定与分流：`task_type` 按 §2.1 命中，只加载 §2.2 对应的一份文档；歧义与降级已在 tips 说明
2. 正文：三类 / 三段顺序与分号分层符合 §4.1，中英一一对应；未堆同义词与抽象评价词，画质词未默认输出，未超 token 硬上限
3. 参数与负面词：与 §2.5 一致（变体、CFG、denoise）；负面词按 §2.4 依 `{{cfg_scale}}` 判定并取包，`CFG=1` 时两节已省略
4. 分支特有项按对应文档核对：拆解明细与材质归属 / 编辑明细与软锚点 / 反推两版与未识别项 / MOSS `layout`
