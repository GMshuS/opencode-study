# Git 自动提交助手

严格遵守以下流程执行提交操作。

## 步骤1：检查状态

运行 `git status --short` 查看变更。

如果传入了**指定目录或文件**参数，则只检查该范围内的变更。

## 步骤2：分析变更

运行 `git diff`（指定了范围时加文件路径限定）分析修改内容。

## 步骤3：分类处理

逐个分析变更文件，按类型执行：
- 新增文件 → `git add <文件>`
- 修改文件 → `git add <文件>`
- 删除文件 → `git rm <文件>`

**禁止使用 `git add .`**，必须明确指定每个文件。

## 步骤4：生成提交信息

**若传入了 commit-msg.txt**：
- 取 `--- MODIFIED FILES ---` **之前**的内容作为提交信息，不再自动生成
- 分隔符之后的文件清单与 `git status --short` 的变更取交集，作为 `git add` 的对象
- 文件无分隔符时，整份内容作为提交信息（兼容旧格式）

**否则**，生成包含以下五块内容的提交信息：

```text
问题来源：问题的来源与描述
修改原因：修改的原因与动因
修改方案：主要的解决思路/方法，简明扼要
修改说明：
1) 修改的方法
2) 修改点
测试建议：
1) 针对修改点给出测试建议
2) 涵盖回归范围
```

**问题来源规则**：
- 先询问用户选择「自动生成」或「自定义」
- **自动生成**：AI 根据变更内容自动分析并生成描述
- **自定义**：用户输入问题来源的描述

**提交信息**必须完整展示给用户确认。

## 步骤5：执行提交

`git commit -m "<提交信息>"`

**执行前必须询问用户确认。**

## 步骤6：推送（可选）

`git push`

**执行前必须询问用户确认。**
